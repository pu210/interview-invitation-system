# AI 測試與人工驗證責任界線

AI 可以協助產生案例、測試骨架、假資料及失敗原因候選，但不能替學員宣告功能正確。

每一個驗證項目都必須由學員完成四件事：

1. 指出它對應哪一項需求或風險。
2. 在固定假資料與固定時間下實際執行。
3. 比較預期結果、實際結果與可回看的證據。
4. 說明測試能證明的範圍，以及仍未證明的部分。

## 自動測試負責

- 狀態轉換與次數。
- 重跑不重複。
- 三個月規則。
- 輸入缺漏及例外流程。
- C#／Java 是否遵循同一份 expected-results。

## 人工驗證負責

- 操作流程是否讓人理解下一步。
- 錯誤訊息是否可行動。
- 模擬信件、日曆及 Drive 結果是否符合情境。
- Log 是否只包含允許的識別與狀態。
- Demo 是否能說清楚需求、設計、證據與限制。

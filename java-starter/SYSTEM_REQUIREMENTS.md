## 0. Codex 必讀指示

1. **六大 P0-A～P0-F 全數必做**，不得將核心功能改成僅靜態畫面。
2. 以本文件定義的業務規則與驗收情境開發；角色及欄位規則同時參照 `ROLE_PERMISSIONS.md`。
3. 本次 Demo **無真實登入、正式資料庫、真實 Email 或 Google Calendar 串接**；Email 與日曆都只能標示為「模擬」。
4. 介面角色切換只用於 Demo；權限、欄位限制、結案鎖定和重複邀約攔截必須在**共用資料修改層**實作。若專案已有後端 API，API 也必須執行相同驗證，不能只隱藏按鈕。
5. 不得自行把「提醒」改成「自動二邀」或「自動婉拒」；這些動作必須由 HR 執行。
6. 未定案的規則以「待確認／Demo 暫定」標註，不要當作已確認需求。
7. **使用者確認修正**：主管可進入「邀約紀錄」**唯讀查看**，但不可編輯。若舊版角色權限 PDF 文字描述與此牴觸，以此修正及 `ROLE_PERMISSIONS.md` 為準。

## 1. 系統目標與範圍

### 1.1 背景與目標

將求職者招募紀錄、邀約信件聯繫、主管面試安排、面試通知和操作歷程集中於同一個 Demo 系統，降低人工追蹤疏漏並提升 HR 與主管協作效率。具體目標如下：

- 集中管理求職者基本資料、邀約紀錄、面試安排及歷程。
- 支援招募進度追蹤與未結案狀態前進／退回。
- 提醒首次 KEYIN 滿 24 小時仍未回覆的二邀，以及推薦主管後 7 天仍無人安排。
- 由主管提供可面試時段，HR 與求職者確認最終面試時間。
- 透過 HTML 通知信範本模擬寄信及日曆事件操作。
- 實作 30 天重複邀約檢查、結案攔截和操作紀錄。

### 1.2 使用者

| 使用者 | 說明 |
|---|---|
| HR | 管理完整招募流程、邀約、狀態、面試協調、信件和日曆模擬、結案與紀錄 |
| 主管 | 唯讀查看邀約紀錄；查看面試安排總表，僅修改指定四類欄位 |
| 求職者 | **非登入角色**；透過外部方式回覆，由 HR 代為登記 |

### 1.3 技術與產品邊界

| 項目 | 規格 |
|---|---|
| Demo 介面 | 可操作網頁，切換 HR／主管角色；不需真實驗證 |
| 四大模組 | 邀約紀錄、面試安排總表、設定與紀錄、信件範本 |
| 資料庫 | 不使用正式資料庫 |
| 資料保存 | 建議使用 `localStorage` 搭配初始 Demo 種子資料；屬建議方案而非強制架構 |
| 後端 | 未正式指定；若已有 Java／Spring Boot 專案，優先沿用現有架構 |
| 信件 | 模擬寄送，不是真正寄出 |
| 日曆 | 模擬建立／更新／取消，不實際串接 Google Calendar |
| 排程 | 每天 10:00 為需求時間；純前端關閉瀏覽器無法持續執行，可於開頁補查和手動觸發 |
| 安全 | 角色切換不具正式身分驗證安全性；程式仍需阻擋越權資料修改 |

## 2. 招募流程與狀態

### 2.1 六種招募狀態

1. `信件聯繫`（建檔初始狀態）
2. `信件溝通中`
3. `時間確認中`
4. `確認面試`
5. `婉拒`
6. `二次邀約未回覆`（二邀處理狀態）

**狀態規則：**

- HR 可以依實際業務將**未結案**案件的狀態向前調整或退回；主管僅能唯讀。
- 每次異動記錄案件 ID、原狀態、新狀態、角色／操作人、時間、必要原因。
- **結案後不可復原、退回或重新啟動原案件**，HR 亦不例外。
- 正常完成條件是 `確認面試` 且**有效的預定面試時間已過**；已取消或被改期取代的面試時間不算有效完成。
- `婉拒` 代表結案；拒絕種類包含「求職者婉拒」、「公司婉拒」，必須留下原因。
- 不得直接刪除招募紀錄。

### 2.2 招募與首次邀約

1. HR 準備建檔，系統先執行 30 天重複邀約檢查（詳見 P0-F）。
2. 檢查通過後，產生唯一案件 ID，保存首次 `keyinAt`，初始狀態為 `信件聯繫`。
3. 當 `keyinAt` 超過 24 小時、尚無回覆、尚未二邀且尚未結案時，顯示「需要二邀」。
4. HR **手動**執行二邀，登記二邀時間及結果；提醒出現不等於已執行二邀。
5. HR 執行二邀後立即設為 `二次邀約未回覆`；**不再另外倒數 24 小時**。
6. 後續有回覆且有面試意願，可改為 `信件溝通中`。

### 2.3 履歷推薦與主管安排

1. HR 推薦求職者給主管，記錄推薦時間。
2. 推薦後 7 天沒有任何主管填寫姓名時，系統提醒 HR，**不得自動婉拒**。
3. 主管可填寫面試主管、面試地點（僅南港／板橋）、備註、**一個或多個**期待安排時間。
4. 主管可以修改其他主管已填寫的上述四類資訊；同一案件最多三位**不同**主管。
5. HR 與求職者協調最終面試時間，必須選擇主管提供且晚於目前時間的期待安排時間，並更新到 `時間確認中` → `確認面試`。

### 2.4 通知、改期、取消及結案

- 確認面試後，HR 選取 HTML 範本、帶入資料、預覽、驗證，依序執行模擬 Email 和模擬日曆建立；分別保存結果。
- **改期**：HR 重新確認時間，更新**原日曆事件**，不得新增重複事件；目前**不重寄 Email**。
- **取消**：HR 填婉拒原因，改為 `婉拒`，取消原日曆事件。
- **正常完成**：`確認面試` 且有效面試時間已過；案件結案後禁止一般修改。

## 3. 核心功能與驗收

### P0-A｜狀態管理與更正

**功能**

- HR 可調整未結案案件狀態（含前進與退回）；主管只能查看。
- 異動歷程包含案件、前後狀態、角色／操作人、時間及必要原因。
- 各模組和角色切換後取得一致的最新資料。
- 結案案件禁止返回未結案狀態；所有角色均適用。
- 已結案案件距最近邀約滿 30 天再面試，**僅 HR** 可用「另立新案」專用入口：產生新 ID、新 `keyinAt`、填寫原因、連結原案件，原案件保持不變；不可讓一般新增功能繞過檢查。

**驗收**

- [ ] HR 可以前進及退回未結案狀態，歷程完整。
- [ ] 主管修改狀態遭阻擋，切換角色後狀態一致。
- [ ] 已結案案件不可重啟（HR 也不可）。
- [ ] HR 可另立新案；主管不可；新舊案件獨立且可追溯。

### P0-B｜首次邀約 24 小時提醒二邀

**觸發條件（全部成立）**：距 `keyinAt` **超過** 24 小時、求職者尚未回覆、尚未執行二邀、尚未結案。

**行為**

- 排程規格為每天 10:00；為 Demo 提供「執行今日排程」與可控制測試時間／種子資料。
- 純前端允許於頁面開啟時補查；不可宣稱瀏覽器關閉時仍能在背景執行。
- 重跑排程不得重複產生同一提醒。
- 清楚區分「已顯示提醒」與「已執行二邀」。
- HR 執行二邀後記錄日期與結果；同步更新為二次邀約未回覆，保存執行結果與狀態異動歷程。

**驗收**

- [ ] 超過 24 小時且符合所有條件才提醒；不足 24 小時不提醒。
- [ ] 已回覆／已二邀／已結案案件不提醒。
- [ ] 重跑不重複；HR 可執行二邀並保留紀錄。

### P0-C｜角色權限與主管安排

**模組權限**

| 模組 | HR | 主管 |
|---|---|---|
| 邀約紀錄 | 查看／操作 | **唯讀查看** |
| 面試安排總表 | 查看／操作 | 查看／僅四類欄位可修改 |
| 設定與紀錄 | 查看／操作 | 不可存取 |
| 信件範本 | 查看／操作 | 不可存取 |

**主管可改四類欄位**：面試主管、面試地點（南港／板橋）、備註（例如 AI／上機考）、期待安排時間。其餘求職者資料、招募狀態、HR 確認時間、求職者回覆、婉拒原因、通知／日曆狀態不可改。詳細權限與例外請參閱 `ROLE_PERMISSIONS.md`。

**限制**

- 可填多個期待安排時間；Demo 可用多行輸入，非空且日期時間應可解析。
- 以有填寫主管姓名判斷是否已有安排；最多三位不同主管。
- 增加第 4 位時必須**整筆拒絕且保留原三位資料**。
- 主管可修改別的主管所填的四類欄位；**依使用者於 2026-10-21 確認修正，時間確認中仍可由主管填寫／修改期待安排時間**，最終面試時間僅由 HR 確認（見權限文件）。
- 欄位白名單、角色限制及結案鎖定在共用資料修改層／API 實施。

**驗收**

- [ ] 主管可唯讀查看邀約紀錄，不能新增／修改／刪除。
- [ ] 主管只能使用允許的模組及四欄編輯權限。
- [ ] 越權寫入遭阻擋，原資料不受影響。
- [ ] 第 4 位主管不可新增；不同角色看同一份資料。

### P0-D｜通知信及模擬日曆

**觸發**：HR 已確認面試。

**嚴格流程順序**

1. 驗證必要面試資料。
2. 確認 HTML 信件範本存在。
3. 驗證必填變數完整替換。
4. 模擬寄送 Email。
5. 模擬建立日曆事件。
6. Email／日曆的執行結果**分開記錄**。

若前置欄位或範本驗證未通過，顯示所有缺漏，**Email 與日曆都不得建立**。

**模擬 Email**：To 為求職者 Email；CC 為面試主管 Email（允許明確標示為假的模擬地址）；使用 HTML 範本。

**模擬日曆事件至少包含**：HR、面試主管、面試時間、地點、會議連結、履歷連結。

**執行與失敗處理**

- Email 與日曆各自記錄 `未執行`／`成功`／`失敗`，失敗須有原因。
- 只重試「失敗／尚未完成」的項目；已成功項目不得再新增成功紀錄。
- 以通知任務識別碼和結果狀態避免按鈕重按／排程重跑造成重複成功信件或日曆事件。
- 改期更新原事件的時間，不增加新事件、不重寄 Email。
- 取消須 HR 提供原因，將案件轉婉拒並取消原日曆事件；正式結案後不可再一般修改。

**驗收**

- [ ] 完整資料依序模擬寄信及建日曆。
- [ ] 缺資料／缺範本時兩者都不執行。
- [ ] 可分別模擬 Email 失敗、日曆失敗，並只重試失敗項目。
- [ ] 重跑不重複，改期更新同一事件，取消時原事件變取消狀態。

### P0-E｜HTML 面試通知信範本與預覽

**範圍**：只需一個「面試通知信」HTML 範本，支援選取、資料帶入、HTML 預覽、必填驗證及模擬寄送前檢查。

**來源規格範例（虛構資料）**

```html
<p>親愛的 <strong>{{姓氏}}{{先生/小姐}}</strong> 您好，</p>
<p>邀請您參與範例科技的 後端工程師 面試。</p>
<p><strong>面試時間：{{面試時間}}</strong></p>
<p>面試地點：南港教學面試室（虛構地點）。</p>
<p>測驗類型：AI。本段用來示範信件範本的 HTML 樣態。</p>
<p>面試前資料：<a href="{{面試前資料}}">填寫資料</a></p>
<p>範例科技 人資部<br>hr@training.example.invalid</p>
```

**必填替換變數**：`{{姓氏}}`、`{{先生/小姐}}`、`{{面試時間}}`、`{{面試前資料}}`。

**驗證與安全**

- 必填值不能為空字串；若缺少範本或欄位，禁止模擬寄送。
- HTML 預覽不得有未替換的 `{{...}}`。
- 文字須正確跳脫 `& < > " '` 等特殊字元。
- URL 須檢查安全可接受的協定，並安全處理 HTML 屬性值，不得直接拼接未處理的使用者輸入。
- 不實作「單次寄送前自由編輯預覽內容」（P-E09）。

**驗收**

- [ ] 姓氏、稱謂、面試時間及資料連結替換正確；HTML 預覽正常。
- [ ] 不留未替換變數；缺欄位／缺範本均拒絕寄送。
- [ ] 含特殊字元的資料可安全正確顯示。

### P0-F｜30 天重複邀約及結案攔截

**檢查範圍**：從邀約當天起算 30 天內的既有邀約紀錄，**不論案件現有狀態**。

**比對優先順序**：`Email → 手機 → 姓名`。比對時忽略空白欄位；Email 建議 trim 並統一大小寫。

| 命中情境 | 處理方式 |
|---|---|
| 30 天內 Email 相同 | 一般新增**直接阻擋**，顯示「30 天內重複邀約」；不提供人工解除 |
| Email 未命中，但手機或姓名相同 | 顯示「可能重複邀約」與既有資料；HR 人工確認同一人→不新增、不同人→可新增；記錄判斷結果 |
| 全部未命中或只命中 30 天以前紀錄 | 可新增，但仍需通過一般必填驗證 |

**另立新案**

- 已結案者距最近邀約滿 30 天再次面試，僅 HR 使用專屬「另立新案」入口，需明確確認、填原因，建立新案件 ID、新 `keyinAt` 和新舊關聯。
- 未滿 30 天不得另立新案，亦不可透過舊案重複建立新案。原案件及其結案資訊不可被修改／刪除；一般新增仍須受重複攔截。
- 新案件不得自動寄信或建日曆，須走完整面試確認流程。

**結案定義**：`婉拒`，或 `確認面試` 且有效預定面試時間已過。取消事件不算正常完成。

**結案後禁止（所有角色）**：新增／更改邀約資訊、修改面試安排、寄信、建立／修改日曆、回復未結案狀態、直接刪除案件。違規操作要有明確錯誤原因，且**不能留下額外資料**。

**驗收**

- [ ] Email 重複一般新增被阻擋；手機／姓名重複須由 HR 確認。
- [ ] 已結案不能修改／重啟；只有 HR 能另立新案且原案不變。
- [ ] 違規操作不新增信件、日曆或面試安排紀錄。

## 4. 設定與紀錄模組

至少保存且可查看下列操作／系統紀錄：

1. 招募狀態異動。
2. 二次邀約提醒與執行。
3. 主管面試安排變更。
4. 模擬 Email 寄送結果。
5. 模擬日曆執行結果。
6. 排程執行結果。
7. 角色權限或業務規則攔截。

其他進階設定並非本次強制規格。

## 5. 六大 P0 Demo 驗收矩陣

| 項目 | 必做操作 | 通過標準 |
|---|---|---|
| P0-A | HR 前進／退回狀態、切角色、嘗試重啟結案案件 | 歷程完整、主管唯讀、結案不可重啟 |
| P0-B | KEYIN 超過／未超過 24h、重跑排程、已回覆／已二邀／結案樣本 | 只提醒符合者、無重複、HR 可完成二邀 |
| P0-C | 切角色、主管改四欄、嘗試改其他欄、新增第 4 位主管 | 權限阻擋且不破壞原資料，角色共享資料 |
| P0-D | 確認面試、兩類失敗、重試、重跑、改期、取消 | 模擬信／日曆分別記錄、去重及更新正確 |
| P0-E | 套用／預覽範本、缺欄位、缺範本、特殊字元 | 正確渲染、不允許寄送不完整內容 |
| P0-F | Email／手機／姓名重複、結案重啟、HR 另立新案 | 攔截正確、新案獨立、舊案不變 |

所有項目需能**從網頁實際操作**驗收，不以程式碼存在替代 Demo。

## 6. 建議開發順序（依原始文件）

1. 共用資料模型、種子資料、角色切換、權限及結案驗證函式。
2. 邀約紀錄、狀態切換、異動歷程及 30 天重複檢查。
3. 主管四欄安排、三位主管上限與 HR 最終時間確認。
4. 24 小時提醒、每日 10:00 單機補查和手動排程。
5. HTML 範本、資料替換、預覽及驗證。
6. 模擬 Email／日曆、分別記錄、失敗重試、去重、改期和取消。
7. 逐項驗收六大 P0，再做介面美化。

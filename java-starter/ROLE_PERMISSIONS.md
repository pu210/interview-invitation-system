# 面談邀約系統｜角色與欄位權限規格

> 來源：`角色權限表.pdf`，並依使用者於 2026-10-20 明確修正  
> 用途：Codex 實作權限控制、介面顯示、資料修改驗證與權限測試  
> 對應總規格：[`SYSTEM_REQUIREMENTS.md`](./SYSTEM_REQUIREMENTS.md)

## 0. 最高優先修正與 Codex 注意事項

**已確認修正：主管可以進入「邀約紀錄」，但只有「唯讀查看」權限。** 原 PDF「權限規則」第 2、3 點及最後的結論寫成主管不可進入邀約紀錄，與原 PDF 模組權限表及系統需求規格書不一致；這些禁止進入的敘述**不適用**，請以本文件的修正版模組矩陣為準。

實作不可只靠隱藏按鈕：所有修改操作都需進入共用權限檢查；若專案有 Java/Spring Boot API，API 也應驗證角色、允許欄位與結案狀態。角色切換只為 Demo，不是正式身份驗證。

## 1. 角色定義

| 角色 | 業務責任 | 角色切換 |
|---|---|---|
| `HR` | 所有四個模組的操作：建檔、招募狀態、二邀、主管安排、面試確認、通知信／日曆模擬、結案、紀錄 | Demo 角色切換，不需登入 |
| `MANAGER`（主管） | 唯讀查看邀約紀錄、查看面試安排總表；在安排表內可共同編輯四類指定欄位 | Demo 角色切換，不需登入 |
| 求職者 | 非系統使用角色，由 HR 登記其回覆與可面試時間 | **無登入入口** |

**共同限制**：即便 HR 具有完整業務操作權，仍受必填驗證、結案鎖定、30 天重複邀約等規則限制。

## 2. 功能模組權限矩陣（已修正）

| 模組 | HR | 主管 |
|---|---|---|
| **邀約紀錄** | 查看、新增、修改及允許的業務操作 | **可進入並唯讀查看；禁止新增、修改、刪除及狀態變更** |
| **面試安排總表** | 查看及操作，須通過業務驗證 | 查看，**僅允許修改四類指定欄位** |
| **設定與紀錄** | 查看、操作 | **禁止進入／存取** |
| **信件範本** | 查看、操作 | **禁止進入／存取** |

### UI 行為

- HR 顯示四大模組入口。
- 主管顯示 **「邀約紀錄」及「面試安排總表」** 兩個入口。
- 主管進入「邀約紀錄」時僅能查閱資料：隱藏／停用新增、編輯、刪除、狀態變更、二邀等操作。
- 主管不可看到「設定與紀錄」「信件範本」入口；直接輸入路徑／呼叫操作也必須被拒絕。
- 僅禁用 UI 不算實作完成；要測試直接修改資料與直接呼叫 API 也失敗。

## 3. 面試安排總表欄位權限

| 欄位 | HR | 主管 | 限制 |
|---|---|---|---|
| 求職者姓名 | 查看／編輯 | 唯讀 | — |
| 應徵職缺 | 查看／編輯 | 唯讀 | — |
| 目前招募狀態 | 查看／編輯 | 唯讀 | HR 僅能更改未結案案件 |
| **面試主管** | 查看／編輯 | **查看／編輯** | 同案最多三位不同主管 |
| **面試地點** | 查看／編輯 | **查看／編輯** | 僅「南港」「板橋」 |
| **備註**（例如 AI、上機考） | 查看／編輯 | **查看／編輯** | 僅在此欄位可改 |
| **期待安排時間** | 查看／編輯 | **查看／編輯** | 可填多個有效時段；`時間確認中` 時主管亦可填寫／修改 |
| HR 確認面試時間 | 查看／編輯 | 唯讀 | 僅 HR 做最終確認 |
| 求職者回覆結果 | 查看／編輯 | 唯讀 | 由 HR 代填 |
| 婉拒原因 | 查看／編輯 | 唯讀 | 結案／取消時 HR 填寫 |
| 信件與日曆執行狀態 | 查看／操作 | 唯讀 | 主管不可觸發寄送／日曆操作 |

**主管唯一可寫入欄位白名單：**

```text
interviewManagers     # 面試主管
interviewLocation     # 面試地點
interviewNotes        # 備註
expectedTimeSlots     # 期待安排時間
```

> 上述英文名稱僅是**建議程式命名**，不是 PDF 指定的資料庫／API 欄位名稱；可配合既有專案命名，但白名單對應的業務欄位不得變更。

## 4. 主管共同編輯規則

1. 主管可查看全部求職者的面試安排資訊，也可以填寫心儀求職者的四類安排欄位。
2. 主管可修改**其他主管**已填寫的這四類資訊；不限制只能修改自己的安排。
3. 同一案件最多三位**不同主管**；第 4 位新增時拒絕整個操作，原先安排不可改變。
4. 主管填寫期待安排時間，不等於主管能自行確認面試；招募狀態與最終確認由 HR 或系統依業務規則處理。
5. **使用者於 2026-10-21 確認修正：案件為「時間確認中」時，主管仍可填寫／修改期待安排時間**；原權限 PDF 的相反限制不適用。最終面試時間仍僅由 HR 確認。
6. 招募案件一旦結案，主管的四類欄位也全部停止編輯。
7. 不可修改求職者基本資料、招募狀態、HR 確認面試時間、求職者回覆、婉拒原因、Email／日曆紀錄。

## 6. 建議權限檢查流程（實作指示，非額外需求）

每一筆資料修改都依序驗證：

1. **角色**：是否允許執行此動作／存取此模組。
2. **案件結案狀態**：是否已是婉拒，或已確認面試且有效面試時間已過；若已結案，拒絕一般修改。
3. **欄位白名單**：對主管的更新請求只允許四類欄位；如 payload 夾帶其他欄位，拒絕整個更新，不要默默接受。
4. **狀態相關限制**：時間確認中仍允許主管更新期待安排時間，最終面試時間僅由 HR 確認。
5. **業務驗證**：地點選項、有效時段、三位主管上限等。
6. **原子性**：只在全部檢查通過時寫入，失敗時原資料不變，並記錄攔截原因。

這是為了落實 PDF 要求的前後端／共用資料層權限檢查，**不代表本專案強制使用特定框架或 API**。

## 7. 權限驗收測試案例

| ID | 操作 | 預期結果 |
|---|---|---|
| RP-01 | 切到主管，開啟「邀約紀錄」 | **可進入並查看全部可展示資料** |
| RP-02 | 主管於邀約紀錄嘗試新增／修改／刪除或更改狀態 | 拒絕，資料不變 |
| RP-03 | 主管開啟面試安排總表、修改四類允許欄位 | 資料成功更新並可由 HR 看見 |
| RP-04 | 主管修改 HR 確認時間、求職者資料、狀態或婉拒原因 | 拒絕，原資料不變 |
| RP-05 | 主管修改其他主管已填的指定四欄 | 允許（其他驗證通過時） |
| RP-06 | 同案已有三位不同主管，再新增第 4 位 | 拒絕，原三位安排完整保留 |
| RP-07 | 案件為「時間確認中」，主管修改期待安排時間 | 允許並保存，案件維持時間確認中；HR 可查看 |
| RP-08 | 主管直接開啟「設定與紀錄」或「信件範本」 | 拒絕存取 |
| RP-09 | 主管嘗試寄信、建立日曆、二邀、結案或另立新案 | 拒絕，沒有副作用 |
| RP-10 | HR 操作未結案案件、確認面試與模擬通知 | 在滿足業務驗證後允許 |
| RP-11 | 任意角色修改已結案案件 | 拒絕，原案不變 |
| RP-12 | 切換 HR → 主管 → HR | 共享相同資料，不因切換覆蓋舊紀錄 |
| RP-13 | 直接呼叫 API／共用資料修改函式，夾帶主管禁寫欄位 | 在資料層被拒絕，不僅是 UI 擋住 |

## 8. 與系統需求文件的關係

- 本文件負責「**誰能看、誰能修改、哪些欄位可寫**」；核心流程、通知、結案、二邀與去重依 `SYSTEM_REQUIREMENTS.md`。
- 權限不代表忽略業務條件。HR 不可重新啟動已結案原案，主管的四類編輯也不適用已結案案件。
- **唯一已知來源衝突已由使用者明確修正**：主管有權唯讀查看「邀約紀錄」；不可因舊版 PDF 的部分敘述而隱藏此模組。
